# 家庭录音笔记人物关系标注 (family-recording-annotation)

> **触发条件**:用户要求标注家庭录音中的人物关系 / 修改录音笔记标题和内容中的人物称呼 / 新录音需要交叉验证身份

## 层1:宏观原则(战略层)

| 原则 | 说明 |
|---|---|
| 主视角标注 | 以用户为主视角,交叉验证所有录音确定人物身份 |
| 保护泛指词 | 只有明确指特定人物本人的才替换,泛指一律保留 |
| 替换后必扫描 | 替换后必须全量扫描残留误替换模式 |
| GET 回验 | 写入后必 GET 回验,确保标注写入成功 |

## 层2:通用规则(战术层)

### 人物关系总表结构(以用户为主视角·交叉验证确认)

**核心家庭成员**(示例结构,实际按用户家庭填写):

| 用户视角 | 孩子视角 | 录音AI常用称呼 | 说明 |
|---|---|---|---|
| 我 | 爸爸 | 我/[用户名] | 创业者 |
| 老婆/妻子 | 妈妈 | 妈妈/妻子 | 用户妻子,孩子妈妈 |
| 孩子 | 自己 | 孩子/小孩/[孩子名] | 孩子信息 |
| 爸爸 | 爷爷 | 爷爷/长辈/讲述者 | 用户父亲 |
| 妈妈 | 奶奶 | 奶奶/长辈/说话人 | 用户母亲 |

**已故长辈**(上坟/口述中提及):按家庭实际情况填写

**其他亲属**:按家庭实际情况填写

### 易混淆点(标注必读)

1. **两个"奶奶"**:用户母亲(活着)vs 用户奶奶(已故,上坟对象)——录音AI总结经常混用
2. **两个"爷爷"**:用户父亲(活着)vs 用户爷爷(已故,口述者)
3. **"姥爷"的两种含义**:用户自己的姥爷 vs 孩子的姥爷(=用户岳父)
4. **"妈妈"的两种含义**:用户妻子 vs 用户母亲
5. **"爸爸"的两种含义**:用户自己(孩子视角)vs 用户父亲
6. **[用户名]不是[错误转录名]**:录音AI可能误转录,用户名字以实际为准
7. **"孩子/小孩"≠全是自家孩子**:别人的孩子、邻居小孩、统计数量等说的是别人,不能机械替换
8. **家族寻根口述**:口述者=用户爷爷(不是爸爸),内容=太爷经历,注意录音时间区分
9. **讲述者与内容中人物的关系**:讲述者说的"爷爷"=讲述者的父亲(=用户爷爷)
10. **地名**:以实际地名为准,注意录音AI可能误转录

### 替换铁律(S级·必读)

**核心原则**:批量将"孩子/小孩/长辈/说话人"替换为具体人物时,机械全局替换会导致大量语义错误。

#### 铁律1:只有明确指特定人物本人的才替换,泛指一律保留

| ✅ 替换为[孩子名] | ❌ 保留原文 | 判断标准 |
|---|---|---|
| 我的孩子 | 别人的孩子 | 别人的孩子不替换 |
| [孩子名]在幼儿园画画 | 同龄孩子 | 对比/泛指不替换 |
| [孩子名]吃鱼卡刺 | 东北孩子数量 | 统计/数量不替换 |
| [孩子名]唱歌 | 朋友家的孩子 | 朋友家的不替换 |
| 给[孩子名]讲故事 | 孩子出生率 | 社会现象不替换 |

#### 铁律2:必须保护这些词不被替换

替换前先标记保护词(regex保护),替换后再恢复:
```
保护词:邻居小孩、楼下小孩、其他小孩、别的小朋友、小朋友、
小女孩、小男孩、大孩子、好孩子、生孩子、带孩子、育儿、
儿童节、保胎、流产、邻居家小姑娘、自己家小孩
```

#### 铁律3:替换后必须全量扫描残留

```python
# 替换后扫描这些误替换模式(把[孩子名]代入检查)
bad_patterns = [
    '同龄[孩子名]', '其他[孩子名]', '[孩子名]数量', '[孩子名]密度',
    '[孩子名]出生率', '适龄[孩子名]', '东北[孩子名]', '[朋友]的[孩子名]',
    '邻居家[孩子名]', '[亲属]的[孩子名]', '南方[孩子名]说话', '东北[孩子名]说话',
]
# 全部应为0,否则需手动修复
```

## 层3:操作流程(执行层)

### 新录音笔记标注流程

```
① Step 1: 读取新笔记(GET /note/detail)
  ↓
② Step 2: 交叉验证人物身份(根据识别特征)
  ↓
③ Step 3: 构建人物标注块
  ↓
④ Step 4: 插入标注 + 更新标题(POST /note/update,3秒间隔防QPS)
  ↓
⑤ Step 5: GET 回验(确认标注写入)
```

### Step 1: 读取新笔记

```python
import requests, re
# 凭证从L1读取
l15 = open('/home/ubuntu/.hermes/MEMORY.md').read()
ak = re.search(r'<API_KEY正则>', l15).group(0)
cid = '[CLIENT_ID]'
HEADERS = {'Authorization': ak, 'X-Client-ID': cid, 'Content-Type': 'application/json'}
BASE = '[API_BASE_URL]'

r = requests.get(f'{BASE}/open/api/v1/resource/note/detail',
    params={'id': NOTE_ID}, headers=HEADERS, timeout=20)
note = r.json()['data']['note']
content = note['content']
```

### Step 2: 交叉验证人物身份

读取笔记内容,根据识别特征识别人物:

| 人物 | 识别特征 |
|---|---|
| 用户 | 提到工作/创业/业务经历;讨论大模型;安排出行开车;被叫[用户名](注意录音AI可能误转录) |
| 用户父亲 | 口述家族历史;专业背景;不信中医 |
| 用户母亲 | 带孩子做手工讲故事;反对炒股;喝中药调理;触景生情提到已故老人 |
| 用户姥爷 | 高龄;摔过腰;请吃饭的人;曾任校长 |
| 孩子 | 童言童语;唱歌表演 |

### Step 3: 构建人物标注块

```python
annotation = f"""📌 **人物关系标注(以用户为主视角)**
- 我=用户
- [孩子名]=儿子
- 爸爸=用户父亲(录音中称"爷爷")
- 妈妈=用户母亲(录音中称"奶奶")

> 📝 [本篇场景说明和关键人物线索]

---

"""
```

### Step 4: 插入标注 + 更新标题

```python
# 插入标注(在"### 📑 智能总结"之前)
if '### 📑 智能总结' in content:
    new_content = content.replace('### 📑 智能总结', annotation + '### 📑 智能总结', 1)
else:
    new_content = annotation + content

# 更新(注意3秒间隔防QPS)
import time; time.sleep(3)
requests.post(f'{BASE}/open/api/v1/resource/note/update',
    headers=HEADERS,
    json={'id': NOTE_ID, 'title': new_title, 'content': new_content},
    timeout=30)
```

### Step 5: GET 回验

```python
v = requests.get(f'{BASE}/open/api/v1/resource/note/detail',
    params={'id': NOTE_ID}, headers=HEADERS, timeout=20).json()
assert '人物关系标注' in v['data']['note']['content'], "标注未写入"
print(f"✅ nid={NOTE_ID} 标注完成 {len(v['data']['note']['content'])} 字符")
```

### 批量处理模板

```python
configs = {

for nid, cfg in configs.items():
```

**QPS限流处置**:连续 write ≥5 次后,每 2 次 sleep 5 秒。触发限流错误时等 60 秒重试。

## 层4:数据来源(验证层)

### 标题命名规范

格式:`【日期·地点·场景】核心内容(在场人物)`

示例:
- `【日期·地点·到达】回父母家第一顿饭:旧平房出售收尾(我+孩子+爸爸+妈妈)`
- `【日期·地点·家族寻根①】爷爷口述:太爷闯关东→沈阳织布厂→地名(我+爷爷+亲属)`
- `【日期·地点·姥爷家】去姥爷家聚餐:孩子唱歌+南北房价(我+孩子+姥爷+亲属)`

## 层5:快速参考(检查清单/铁律表)

### 标注前检查清单

- [ ] 是否读取了笔记内容(GET /note/detail)?
- [ ] 是否根据识别特征交叉验证了人物身份?
- [ ] 是否区分了易混淆点(两个奶奶/两个爷爷/姥爷两种含义等)?
- [ ] 人物标注块是否按主视角格式构建?

### 替换前检查清单

- [ ] 是否只替换明确指特定人物本人的词(泛指一律保留)?
- [ ] 是否标记了保护词(邻居小孩/其他小孩/小朋友等)?
- [ ] 替换后是否全量扫描了残留误替换模式?
- [ ] 误替换模式扫描结果是否全部为 0?

### 写入后检查清单

- [ ] 是否 GET 回验了(确认标注写入)?
- [ ] 标题是否按命名规范格式?
- [ ] 批量处理时是否每篇间隔 3 秒防 QPS?
- [ ] 触发限流时是否等 60 秒重试?

### 禁止行为清单

- ❌ 机械全局替换"孩子/小孩/长辈/说话人"(会导致大量语义错误)
- ❌ 替换别人的孩子/邻居小孩/统计数量(泛指一律保留)
- ❌ 替换前不标记保护词
- ❌ 替换后不扫描残留误替换模式
- ❌ 写入后不 GET 回验
- ❌ 批量处理不间隔(触发 QPS 限流)
- ❌ 凭印象判断人物身份(必交叉验证)
