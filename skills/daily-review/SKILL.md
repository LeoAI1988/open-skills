# 每日投资复盘

## 边界

本 Skill 提供记录和分析框架，不保证收益，不直接代用户下单。只在用户主动请求时运行；涉及账户截图、成交记录和持仓时，按敏感金融数据处理，不写入公开文件。

## 数据准备

优先级：

1. 用户确认的成交记录与账户快照；
2. 券商导出的原始记录；
3. 可靠行情和公告来源；
4. OCR 或人工转录，作为待核对数据。

采集：日期、市场、标的、方向、数量、成交价、费用、持仓、现金、总资产和用户当时的计划。对行情和新闻记录来源与时间戳。

## 执行流程

### 1. 核对数据

检查成交、持仓和资产是否能互相解释。OCR 小数点、币种、复权口径和成本算法容易出错；冲突时标为待确认，不擅自选择对用户更有利的数字。

### 2. 复盘市场

概括指数、行业、成交、公告和宏观事件。每个影响判断至少给一个支持证据和一个反向证据；将事实、市场解释和个人推断分开。

### 3. 复盘操作

对每笔交易回答：

- 是否符合事前计划；
- 触发条件是否真实发生；
- 下单价格、仓位和时机是否偏离；
- 结果来自策略、市场波动还是运气；
- 有哪些可复用和应停止的行为。

### 4. 形成次日情景

只给条件化计划，不写确定性预测：

| 情景 | 可观察条件 | 风险 | 待确认动作 |
|---|---|---|---|
| 偏强 |  |  |  |
| 中性 |  |  |  |
| 偏弱 |  |  |  |

所有具体交易动作须由用户自行确认。

## 报告模板

```markdown
## 核心结论

## 数据范围与可信度

## 持仓与成交核对

## 市场事实与反向证据

## 计划执行偏差

## 次日情景表

## 待用户确认项
```

## 质量检查

- 数据、币种、时间和来源已核对；
- 未把注资或转账当作收益；
- 未用单一截图替代真实行情；
- 结论同时包含反向证据；
- 未暴露账户号、姓名、联系方式、持仓截图或精确资产数据；
- 未把分析写成保证收益的指令。
