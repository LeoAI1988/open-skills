# 投资绩效分析 Skill

## 一、用途

为个人投资者生成结构化的绩效报告，回答三个核心问题：
1. **赚了多少 / 亏了多少**（精确数字 + 收益率）
2. **赚得怎么样**（相对基准、仓位效率、回撤控制）
3. **下一次怎么改进**（执行偏差诊断 + 策略漏洞清单）

## 二、触发条件

任一命中即启动：
- 用户主动请求："绩效分析""操盘统计""账户表现""季度回顾"
- 每周/每月/每季度的周期性复盘
- 重大策略变更前后（对比新旧策略效果）
- 单标的回溯："X 标的从 Y 月至今盈亏""X 累计收益""X 回本情况"（回溯跨度 ≥ 1 个月）

## 三、核心方法论

### 3.1 数据采集（三源对照）

| 优先级 | 数据源 | 用途 |
|--------|--------|------|
| 主 | 复盘笔记 / 交易日志 | 每日持仓快照、操作记录、盈亏 |
| 辅 | 工作上下文 / Session 历史 | 补全复盘缺失的字段 |
| 兜底 | 原始截图 OCR | 复盘与实际不符时，以截图为准 |

**铁律：**
- 数据冲突时，**原始截图 > 复盘笔记 > 工作上下文 > Session 记录**
- 不依赖正则提取数字（格式不统一），必须逐字读取
- 缺失数据标注"推算值"，不编造精确数字
- 用户指定起止日与实际数据范围不符时：用已有数据反推期初，标注"推算"

### 3.2 注资剥离（最易出错）

**核心原则：注资是本金，不是收益。**

```
累计盈亏 = 期末总资产 - 期初总资产 - Σ(期间注资)
```

- 注资金额与时间**只以用户口头确认为准**，不从记忆或历史推算
- 每次报告前必须向用户确认注资总额
- 注资时间 ≠ 策略变更时间，两者不能混淆

### 3.3 逐日链式验证

**目的：发现数据断点。**

```python
for each trading day:
    expected = prev_day_total + current_day_pnl
    gap = current_day_total - expected
    if abs(gap) > 容差阈值:
        # 断链！排查原因
```

**常见断链类型：**

| 类型 | 特征 | 处理 |
|------|------|------|
| 隔夜跳空 | 前日→次日 gap 为正 | 日盈亏=日内涨跌，标注即可 |
| 周末跳空 | 周五→周一 gap 可正可负 | 同上 |
| 注资日 | gap ≈ 注资金额 | 标注"🔑注资" |
| 数据错误 | gap 无合理解释 | 标注"❓存疑"，追查数据源 |

**关键：总减法是数学恒等式。** 当总减法（期末-期初-注资）与逐日累加不一致时，**以总减法为准**，追查逐日数据的断点，而不是怀疑总减法。

### 3.4 收益率公式

**累计收益率 = 累计盈亏 / 平均仓位占用资金**

- 平均仓位占用资金 = 逐日证券市值的算术平均
- 不要用 `累计盈亏/期初总资产`（含闲置现金，会低估收益）
- 反映"实际在用的钱赚了多少"

**CAGR（复合年化增长率，核心指标）：**

```
CAGR = (期末总资产 / 期初总资产) ^ (250 / 交易天数) - 1
```

- 250 ≈ A 股全年交易日数（已扣节假日）
- 反映复利效应，比简单线性年化更真实
- 简单年化（`收益率 × 250/天数`）仅作参考对照

**目标资产推算：**

```
目标天数 = log(目标资产/当前总资产) / log(1 + 日均复利率)
日均复利率 = (1 + CAGR) ^ (1/250) - 1
```

输出时换算为自然月数（÷30.44，含节假日）。

### 3.5 策略阶段分离

如果统计区间内发生过策略变更，所有盈亏指标必须**分三段输出**：

| 阶段 | 范围 |
|------|------|
| 旧策略期 | 起始日 → 策略切换前一日 |
| 新策略期 | 策略切换日 → 截止日 |
| 全周期 | 起始日 → 截止日 |

切换日期由用户指定，不从记忆推算。

## 四、执行流程

### Step 1：确认统计参数

向用户确认：
- 起止日期
- 期初总资产（不确定时索取原始截图）
- 期间注资记录
- 是否有策略变更（如有，切换日期）

### Step 2：采集逐日数据

按"3.1 数据采集"三源对照，提取每个交易日的：
- 总资产、证券市值、可用资金
- 当日盈亏、累计盈亏、仓位%
- 持仓明细（标的、数量、成本、现价、盈亏）
- 当日操作
- 策略评分（如有）

### Step 3：链式验证

按"3.3 逐日链式验证"，找出所有断点并标注原因。

### Step 4：计算指标

按"3.4 收益率公式"计算累计盈亏、收益率、CAGR、目标推算。

### Step 5：生成报告

按"五、报告框架"输出。

## 五、报告框架

### 5.1 核心指标表

| 指标 | 数值 | 说明 |
|------|------|------|
| 统计时长（自然日） | | 含周末和节假日 |
| 交易天数 | | 实际开盘日 |
| 期初/期末总资产 | | 分含/不含注资 |
| 期间注资 | | 每笔金额 + 日期 |
| 首次盈利日 | | 累计盈亏转正的日期 |

### 5.2 盈亏指标（分策略阶段）

| 指标 | 旧策略期 | 新策略期 | 全周期 |
|------|----------|----------|--------|
| 累计盈亏 | | | |
| 累计收益率 | | | |
| 简单年化 | | | |
| CAGR（复利年化） | | | |

### 5.3 统计指标

- 日均涨跌额 / 日均涨跌%
- 单日最大涨幅（元/%/日期） / 单日最大跌幅（元/%/日期）
- 单日最大涨跌贡献标的
- 累计盈利 TOP3 标的 / 累计亏损 TOP3 标的
- 平均仓位% / 平均仓位占用资金

### 5.4 逐日行情表

```
日期 | 星期 | 总资产 | 市值 | 日盈亏 | 日收益率 | 仓位 | 累计盈亏 | 关键操作
```

> 日收益率 = 当日涨跌额 ÷ (当日市值 − 当日涨跌额)

### 5.5 策略执行分析

- **做的好的**：纪律执行到位、时机把握准确的案例
- **做的不足的**：偏离计划的案例（追高/超配/未及时止损等）
- **时机把握评估**：按类型（上涨兑现/下跌离场/追高入场/FOMO 等）逐项评分

### 5.6 策略体系诊断（8 维度）

产业链判断 / 建仓时机 / 卖出判断 / 仓位管理 / 信息采集 / 盘中监控 / 复盘质量 / 技能配置

每维度 1-10 分 + 策略漏洞清单（含修复状态）。

### 5.7 跨产业视角

跳出当前主线产业链，审视持仓集中度：
- 列出 20+ 个完全不相关的产业带标的（消费/医疗/能源/基建/金融/农业等）
- 关注度打分（1-5 星）
- 锁定 TOP3 重点关注（需有催化剂逻辑）
- 原则：不为买而找，从第一性原理出发

### 5.8 BestMinds 思维审视

作为绩效检查清单，不产生买卖指令：

1. **霍华德·马克斯「位置感」**：当前仓位、盈亏、市场环境在周期中的位置？应该激进还是保守？
2. **瑞·达里奥「分散化」**：持仓相关性？尾部风险？分散化是否充分？
3. **彼得·林奇「认知完整性」**：每个持仓为什么买？赚的是什么钱？有信息优势还是运气？

### 5.9 改进建议

按 P0/P1/P2 优先级输出。

## 六、常见陷阱（整合）

### 陷阱 1：单标的回溯漏看减仓节点

**症状**：用户问"X 标的累计盈亏"，直接用最终持仓算盈亏，漏掉中间的减仓/清仓操作。

**正确做法**：
- 任何标的清仓节点，必查"减仓→清仓"之间所有记录，重建完整时间线
- 例如 22,000 份 → 17,000 → 5,000 → 0 的三段式减仓，不能只看首尾

### 陷阱 2：注资被算成收益

**症状**：用户中途注资，总资产上升，被误算成盈利。

**正确做法**：注资必须从累计盈亏中扣除（见 3.2）。

### 陷阱 3：总减法与逐日累加不一致时选错

**症状**：总减法 = 3,282，逐日累加 = 2,995，选择后者。

**正确做法**：总减法是数学恒等式，以它为准，追查逐日数据为何有断点（通常是隔夜/周末跳空未计入）。

### 陷阱 4：数据覆盖率低却不出质量评估

**症状**：14/35 个交易日有数据（覆盖率 40%），照常出报告不提示。

**正确做法**：覆盖率 < 60% 时，报告必须包含"可信/存疑/覆盖率"质量评估段，不拒绝出报告，但不掩饰。

### 陷阱 5：同一天出现多个总资产值

**症状**：同一日期记录了两个差异很大的总资产值（例如差 47%）。

**正确做法**：必须给修订说明表，说明取高/取低/标推算的理由（账户类型/统计口径/出金等），并提供"反向场景"让用户能验证。

### 陷阱 6：OCR 成本漂移

**症状**：券商 APP 显示的持仓成本与真实加权成本不符（可能显示为建仓初价或 FIFO 重算值）。

**正确做法**：以加权成本为准，手动计算：

```
加权成本 = Σ(每次买入价 × 数量) / 总数量
```

## 七、输出规范

1. **数据精确性优先**：宁可慢，不能错。数据不全不交差。
2. **注资以用户为准**：不凭推算，不凭记忆。
3. **分策略段输出**：所有盈亏指标三段并列。
4. **不伪造精度**：无复盘覆盖的日期标"推算值"。
5. **偏差分析客观**：不美化执行情况，买高了就说买高了。
6. **报告同步存档**：生成后写入用户的笔记系统 + 工作上下文。
7. **BestMinds 仅作框架**：不产生具体买卖指令。
