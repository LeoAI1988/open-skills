# 技能管理 Skill

管理 SKILL.md 的完整生命周期：创建、安全审查、安装部署。

## 一、技能创建

**触发：** "帮我创建一个技能""封装这个工作流""写一个 SKILL.md"

### 设计原则

好的技能必须满足：
- **触发明确**：用户说什么话时该启用这个技能（精确的触发词列表）
- **非内置**：确认不是 Hermes/Claude/Agent 已有的原生能力
- **步骤可执行**：每一步都能落地，不写空话
- **可验证**：完成后有明确的验证标准
- **可复用**：不是一次性任务，而是反复出现的工作流

### 创建流程

1. **结构化访谈** — 收集：
   - 触发场景（用户什么时候会用）
   - 输入（用户提供什么）
   - 输出（用户期望得到什么）
   - 工作流（分几步完成）
   - 已知陷阱（过去踩过什么坑）

2. **设计触发描述** — 写 frontmatter：
   ```yaml
   ---
   name: kebab-case-name
   description: 一句话说清用途+触发场景
   tags: [tag1, tag2]
   trigger: [关键词1, 关键词2]
   ---
   ```

3. **设计工作流** — 步骤化、有序、可执行

4. **提炼陷阱** — 从失败模式中提取"不要做什么"

5. **生成 SKILL.md** — 符合 frontmatter 规范

6. **质量自检** — 模拟一个新用户首次加载，能否看懂、能否执行

### 文件结构规范

```
skill-name/
├── SKILL.md           # 主文档（必须）
├── references/        # 参考资料（可选）
│   ├── example.md
│   └── pitfalls.md
├── templates/         # 模板（可选）
└── scripts/           # 脚本（可选）
```

## 二、技能安全审查

**触发：** "审查这个技能""这个外部技能安全吗""安装前检查"

### 审查范围

| 检查项 | 重点 |
|--------|------|
| frontmatter 声明 | name/description/tags 是否合理 |
| scripts/ 脚本 | 所有可执行代码 |
| 外部命令 | 网络请求、文件系统、CLI 调用 |
| 凭证引用 | 环境变量、API key |
| 动态执行 | eval/exec/反序列化 |

### 检查清单

- [ ] allowed-tools 声明是否合理（不过度授权）
- [ ] 是否有未声明的网络访问（curl/wget/requests）
- [ ] 是否有未声明的文件系统写操作
- [ ] 是否硬编码或外泄 API key / token
- [ ] 脚本是否有 eval/exec 动态执行
- [ ] 是否有 package install（pip/npm/brew）
- [ ] 是否有可疑的混淆代码

### 输出格式

```
结论：✅ 可安装 / ⚠️ 谨慎安装 / ❌ 拒绝
风险等级：LOW / MEDIUM / HIGH
风险点：
  1. [具体风险] — [建议]
  2. ...
```

## 三、技能安装

**触发：** "安装这个技能包""从外部导入技能"

### 流程

1. **下载技能包**（zip/tar/git clone）
2. **安全审查**（按"二"流程）
3. **解压到 skills 目录**（如 `~/.hermes/skills/custom/`）
4. **验证目录结构**（SKILL.md 必须在根目录）
5. **测试触发**（用一个触发词验证能否加载）
6. **报告结果**（成功/失败 + 具体原因）

### 常见坑

| 坑 | 症状 | 解决 |
|----|------|------|
| 目录嵌套错误 | SKILL.md 不在根目录 | 检查解压后的层级 |
| frontmatter 损坏 | 加载报错 | 检查 YAML 格式 |
| 依赖缺失 | 脚本执行失败 | 提示用户安装依赖 |
| 编码问题 | 中文乱码 | 统一 UTF-8 |
