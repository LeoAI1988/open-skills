# 战略思考系统

## 适用场景

适合市场进入、产品方向、增长停滞、资源配置、融资并购和业务转型。简单执行任务不需要套用完整框架。

## 五个框架

### 1. 观察—判断—行动—反馈

把大问题拆成可验证的小决策：观察现状，形成假设，执行最小动作，收集反馈，再更新判断。

### 2. 多视角检查

不用具体人物名字，使用角色视角：

| 视角 | 核心问题 |
|---|---|
| 周期位置 | 当前处于扩张、拥挤、转折还是收缩阶段 |
| 风险分散 | 风险是否集中，尾部情景是什么 |
| 认知完整 | 我们真正理解的因果链是什么 |
| 逆向失败 | 如果项目失败，最可能因为什么 |
| 长期稳定 | 多年后仍不会改变的需求是什么 |

### 3. 多角色辩论

根据问题选择产品、工程、销售、财务、风控、客户和竞争者等角色。每个角色必须基于证据提出支持、反对和未知项；分歧点就是需要验证的关键变量。

### 4. 反向挑战

至少回答：

1. 如果当前倾向是错的，最可能错在哪里；
2. 竞争者会怎样利用我们的选择；
3. 哪个外部变化会让结论失效；
4. 不做这件事的机会成本是什么。

### 5. 商业基础拆解

检查真实需求、供给优势、单位经济、获客、交付、现金流、合规和扩展性。任一关键环节没有证据时标记为假设。

## 执行流程

1. 把问题改写成明确的决策问题。
2. 列出目标、约束、时间、已有倾向和 3–5 个关键变量。
3. 只选择最相关的 2–3 个框架。
4. 区分事实、假设、观点和未知项。
5. 主动寻找反向证据。
6. 给出选项矩阵、可逆性和最小验证动作。
7. 提供倾向性建议和失效条件，由用户最终决定。

## 输出模板

```markdown
## 决策问题
## 目标与约束
## 已确认事实 / 假设 / 未知项
## 关键分歧
## 选项矩阵
| 选项 | 收益 | 风险 | 成本 | 可逆性 | 适用条件 |
|---|---|---|---|---|---|
## 最小验证动作
## 倾向性建议与失效条件
```

## 检查

避免框架堆砌、确认偏误、伪造专家意见和替用户做决定。公开产物不包含姓名、联系方式、内部项目代号、客户信息或私人财务数据。
