# 顶级思维决策系统

## 用途

为复杂商业、产品和投资问题提供多维度分析，不替用户做决定，而是帮助识别关键变量、反向证据和失效条件。

适用场景：

- 进入哪个市场或选择哪个产品方向；
- 寻找新的增长点；
- 诊断业务停滞；
- 融资、并购、转型和重大资源投入；
- 高不确定性的投资或风险决策。

简单执行任务不需要套用完整框架。

## 五大框架

### 1. OODA 执行循环

```text
观察 Observe → 判断 Orient → 决策 Decide → 行动 Act
      ↑                                  ↓
      └──────── 反馈 Feedback ──────────┘
```

不要试图一次想清所有问题。先形成可验证假设，执行最小动作，再依据反馈调整。

### 2. 公开思想者视角

| 思想者 | 公开框架视角 | 核心问题 |
|---|---|---|
| 霍华德·马克斯 | 周期与位置感 | 当前处于周期什么位置，市场共识是否过度？ |
| 瑞·达里奥 | 分散与相关性 | 风险是否集中，尾部情景是否得到覆盖？ |
| 彼得·林奇 | 认知完整性 | 我们真正理解的业务、因果链和收益来源是什么？ |
| 查理·芒格 | 逆向思维 | 如果想让这件事失败，最可能怎么失败？ |
| 杰夫·贝佐斯 | 长期主义 | 多年后什么仍不会改变，当前选择是否服务于它？ |

这些名称用于标注公开思想来源。不要伪造引语、把推演内容冒充本人意见，或声称得到其认可。重大决策至少选三个相关视角，不必全部使用。

### 3. 多角色辩论

根据问题选择不同角色：

| 问题类型 | 建议角色 |
|---|---|
| 投资决策 | 多头分析师、空头分析师、风控官、宏观研究员 |
| 产品决策 | 产品经理、工程师、设计师、销售、客户 |
| 战略决策 | CEO、CFO、CTO、竞争对手和监管视角 |

每个角色必须给出支持、反对、证据和未知项。专家之间应当出现真实分歧；分歧点就是需要继续验证的关键变量。

### 4. 反向挑战

至少回答：

1. 如果当前倾向是错的，最可能错在哪里？
2. 竞争对手会怎样利用我们的选择？
3. 哪个外部变化会让结论失效？
4. 如果什么都不做，机会成本是什么？
5. 十年后回看，什么仍然重要？

### 5. 商业基础拆解

| 层级 | 问题 |
|---|---|
| 需求 | 用户真正要解决什么问题？ |
| 供给 | 为什么我们能比替代方案做得更好？ |
| 商业模型 | 收入、成本、现金流和单位经济是否成立？ |
| 增长 | 获客、交付和组织是否可扩展？ |
| 风险 | 合规、集中度、尾部风险和退出条件是什么？ |

任一关键环节缺乏证据时，把它标记为假设，不得直接当成事实。

## 执行流程

### 1. 明确决策问题

```text
决策问题：[需要选择什么]
目标：[希望获得什么结果]
当前倾向：[已有判断]
约束：[资金、时间、资源、合规]
关键变量：[3–5 个]
决定期限：[日期或触发条件]
```

### 2. 选择框架

| 问题特征 | 推荐组合 |
|---|---|
| 高不确定性 | OODA + 反向挑战 |
| 多方利益 | 多角色辩论 + 商业拆解 |
| 长期影响 | 公开思想者视角 + 情景分析 |
| 商业机会 | 商业拆解 + 反向挑战 |

只选最相关的 2–3 个，不堆砌全部框架。

### 3. 区分证据状态

把输入分为：

- 已确认事实；
- 有来源但尚未复核的数据；
- 用户或团队观点；
- 分析假设；
- 仍未知的关键问题。

主动寻找反向证据，不要只补强用户最初的倾向。

### 4. 形成决策矩阵

```markdown
| 选项 | 收益 | 风险 | 成本 | 可逆性 | 适用条件 |
|---|---|---|---|---|---|
| A | ... | ... | ... | ... | ... |
| B | ... | ... | ... | ... | ... |
```

### 5. 给出最小验证动作

优先选择成本低、可逆、能区分关键假设的实验。说明需要什么证据、何时复盘、什么结果会改变建议。

### 6. 综合结论

给出倾向性建议、理由、主要风险、失效条件和最终由用户确认的决策点。

## 输出模板

```markdown
## 决策问题
## 目标与约束
## 已确认事实 / 假设 / 未知项
## 选用框架与分析
## 关键分歧
## 选项矩阵
## 最小验证动作
## 倾向性建议与失效条件
```

## 常见陷阱

- 只说利好：强制回答反向挑战问题。
- 五个框架全部堆上：只保留最相关的 2–3 个。
- 替用户做决定：给建议和条件，不替用户下最终指令。
- 伪造专家共识：角色观点必须来自证据与明确假设。
- 把公开人物名字全部删除：保留准确来源，但不编造其言论。
- 输出私人财务或客户信息：公开报告只保留必要的脱敏事实。

## 检查

- [ ] 问题、目标和约束是否清楚？
- [ ] 事实、观点、假设和未知项是否分开？
- [ ] 是否使用了反向证据？
- [ ] 公开思想者的名称与观点来源是否准确？
- [ ] 是否给出可逆的最小验证动作？
- [ ] 是否没有泄露用户、家人、客户、联系方式或账号凭证？
