# AI 智能体代人产品的设计哲学 Skill

## 一、用途

当设计"AI 智能体替主人办事"的产品时（撮合/匹配/对接/代理），提供设计哲学指导，避免做成传统的"用户手填档案"平台。

**适用产品：**
- Agent 撮合平台（替主人找朋友/资源/项目）
- AI 代理服务（替主人对接/谈判/执行）
- 智能体社交网络（智能体之间协作）

## 二、核心理念

### 理念 1：宏大 + 头皮发麻

产品定位必须有"宏大叙事"+"头皮发麻的震撼感"。

✅ 好：
- "让两个智能体替主人交朋友"
- "AI 时代的社交网络，智能体先行"
- "主人在睡觉，智能体在帮他找合伙人"

❌ 平庸：
- "一个匹配平台"
- "帮你认识新朋友"
- "社交 App"

### 理念 2：主人零参与

**核心铁律：** 主人不填档案、不刷列表、不逐个聊天。

| 传统平台 | Agent 平台 |
|---------|-----------|
| 主人手填资料 | 智能体自动读主人记忆生成档案 |
| 主人刷列表 | 智能体自动筛选+匹配 |
| 主人逐个聊天 | 智能体先对接，合适了再通知主人 |
| 主人主动刷新 | 智能体主动推送匹配结果 |

**主人的全部操作：** 点按钮复制 curl → 粘 verify_code → 看匹配结果决定是否同意。

### 理念 3：形态命名

避免传统社交/婚恋词汇，用"找"系列：

| ✅ 推荐 | ❌ 避免 |
|---------|---------|
| 找朋友 | 相亲 |
| 找资源 | 约会 |
| 找项目 | 配对 |
| 找合伙人 | 交友 |
| 智能体对接 | 匹配 |

## 三、信息流设计

### 传统 vs Agent 平台

```
【传统】
用户注册 → 填档案 → 刷列表 → 右滑喜欢 → 聊天 → 约见

【Agent 平台】
主人点按钮 → 智能体读记忆生成档案 → 智能体对接 → 匹配度高 → 通知主人 → 主人同意 → 撮合
```

### 信息流的 5 个关键点

1. **档案由智能体生成**（不是主人填）
2. **匹配由智能体计算**（不是主人刷）
3. **初次接触由智能体完成**（不是主人聊）
4. **最终决定由主人做**（智能体不替主人决定）
5. **隐私由主人控制**（智能体不暴露主人不想暴露的）

## 四、隐私分级

主人可选档案的暴露颗粒度：

| 级别 | 暴露内容 | 时机 |
|------|---------|------|
| L1 公开 | 平台+能力标签+需求类型 | 默认 |
| L2 元数据 | + 记忆统计（文件数/字符数） | 默认 |
| L3 画像 | + 脱敏后的主人画像 | 双方同意后 |
| L4 全文 | + 完整记忆内容 | 双方同意后 |

**铁律：** 默认 L2。撮合成功后双方同意才升级到 L3/L4。

## 五、视觉风格

### 默认风格：黑底荧光绿终端

```css
--bg: #000000;
--green: #00F58A;
--white: #FFFFFF;
--gray: #666666;
```

### 设计原则

- **极简：** 不堆砌元素
- **高对比度：** 黑底荧光绿
- **科技感：** 等宽字体、终端美学
- **不用 emoji：** SVG 图标自绘
- **不用素材图：** 纯 CSS/SVG

### 参考风格

- mr.io（极简）
- Linear（深色+荧光）
- Vercel（黑白极简）
- yizhou.chat（终端风）

## 六、智能体对接设计

### 智能体如何"读"主人

智能体通过读取主人的：
- 笔记系统（Get 笔记/Notion）
- 记忆文件（L1/L2）
- 项目代码（GitHub）
- 对话历史

生成主人的"脱敏画像"。

### 智能体如何"对接"

两个智能体通过 API 交换：
- `agent_bio`（自述）
- `capabilities`（能力标签）
- `owner_summary`（脱敏画像）
- `needs`（当前需求）

对接后计算匹配度，高于阈值才通知主人。

## 七、常见设计陷阱

### 陷阱 1：做成"填档案"平台

**症状：** 让主人填一堆表单。

**正确：** 智能体自动读记忆生成档案，主人只确认。

### 陷阱 2：智能体替主人做决定

**症状：** 智能体自动同意匹配。

**正确：** 智能体只推荐，主人做最终决定。

### 陷阱 3：暴露太多隐私

**症状：** 智能体把主人记忆全文推送。

**正确：** 分级暴露，默认 L2，撮合后才升级。

### 陷阱 4：用婚恋/社交词汇

**症状：** 用"相亲""约会""配对"。

**正确：** 用"找朋友""找资源""对接"。

### 陷阱 5：定位平庸

**症状：** "又一个社交 App"。

**正确：** 宏大叙事 — "AI 时代的社交网络，智能体先行"。

## 八、技术栈推荐

- **后端：** FastAPI + SQLModel + SQLite/PostgreSQL
- **前端：** 手写 HTML（不依赖框架）
- **隧道：** serveo.net / Cloudflare Tunnel
- **智能体协议：** curl + JSON（最简，跨平台）

**原则：** MVP 阶段越简单越好，不引入 React/Vue/Kubernetes 等复杂度。
